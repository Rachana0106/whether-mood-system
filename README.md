## 📖 About the Project

**Micro-Mood Weather System Pro** is an interactive web application that connects a user’s mood with weather conditions.

The project goes beyond a traditional weather application by allowing users to:

- Check current weather conditions
- Record their current mood
- Track mood entries
- Build daily streaks
- Unlock achievements
- View mood analytics
- Receive personalized suggestions
- Use a profile-based experience
- Enjoy dynamic visuals based on weather and mood

The interface uses colorful gradients, animated weather backgrounds and glassmorphism components to create an immersive experience.

---

## 🎯 Project Objective

The main objective of this project is to combine three ideas in one application:

```text
Weather Information
        +
Mood Tracking
        +
Personalized Suggestions
```

The platform is designed to make daily weather information feel more personal, interactive and useful.

Instead of only showing temperature and weather conditions, it also helps users reflect on how they feel and discover suitable activities, food, music and outfit suggestions.

## 🚀 How to Run the Project

### Method 1: Open Directly

1. Download or clone the repository.
2. Open the project folder.
3. Double-click `index.html`.
4. The application will open in your browser.

### Method 2: Clone with Git

```bash
git clone https://github.com/Rachana0106/whether-mood-system.git
```

Open the project folder:

```bash
cd whether-mood-system
```

Then open `index.html`.

### Method 3: Use VS Code Live Server

1. Open the repository in VS Code.
2. Install the **Live Server** extension.
3. Right-click `index.html`.
4. Select **Open with Live Server**.

## 🔐 Security Considerations

Because the project includes login and user-profile functionality, a production version should not store sensitive passwords directly in browser storage.

A secure production version should use:

- Backend authentication
- Password hashing
- HTTPS
- Secure sessions or tokens
- Input validation
- Rate limiting
- Protected API keys
- Secure database storage
- Content Security Policy
- Proper error handling

## 📝 Recommended Improvements

### Rename the Repository

The current repository name is:

```text
whether-mood-system
```

A better and correctly spelled name would be:

```text
weather-mood-system
```

**Weather** refers to climate conditions.  
**Whether** is used when expressing alternatives.

### Separate the Code

The current `index.html` file is very large.

For better organization, split it into:

```text
weather-mood-system/
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── weather.js
│   ├── mood.js
│   ├── auth.js
│   ├── analytics.js
│   └── app.js
└── README.md
```

This will make the project easier to:

- Read
- Maintain
- Debug
- Improve
- Present to recruiters

### Protect API Keys

When you connect a weather API, do not expose private API keys directly in a public GitHub repository.

Use environment variables or a backend proxy in a production version.
